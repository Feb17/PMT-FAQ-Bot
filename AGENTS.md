# AGENTS.md

## Repository shape
- This repo is a Python 3.11 Dockerized PMT FAQ RAG service, not a Python package install; imports assume running from `pmt_faq_bot/` with `src/` on `sys.path`.
- `pmt_faq_bot/src/main.py` is the real entrypoint (`python -m src.main` in Docker) with subcommands: `serve`, `ingest`, `status`, `process-images`.
- Runtime flow: FastAPI `/v1/chat/completions` -> `server/chat.py` -> standalone rewrite for multi-turn -> `retrieval.py` hybrid dense+BM25 recall -> TEI rerank -> vLLM proxy -> sources/images appended.
- The old `models/rag-ingest` tree mentioned in history is intentionally not used; source for the bot image is `pmt_faq_bot/`.

## Commands that matter
- Initial env: `cp app-vm-3-17.env.example .env`.
- Build API image: `docker compose --env-file .env -f compose.app-vm-3-17.yml build pmt_faq_bot`.
- Run API + WebUI: `docker compose --env-file .env -f compose.app-vm-3-17.yml up -d pmt_faq_bot open-webui`.
- Process images before ingest: `docker compose --env-file .env -f compose.app-vm-3-17.yml --profile image-processing run --rm pmt_faq_bot_image_process`; default OCR is PaddleOCR, which is not in `requirements.txt`/current wheels, so use `IMAGE_OCR_ENGINE=none` or provide PaddleOCR wheels/custom image.
- Ingest docs: `docker compose --env-file .env -f compose.app-vm-3-17.yml --profile ingest run --rm pmt_faq_bot_ingest`.
- Verify running API: `curl -s http://127.0.0.1:8090/healthz` and `curl -s http://127.0.0.1:8090/v1/models`.
- Open WebUI should point to `http://pmt_faq_bot:8088/v1` from inside the compose network.

## Data and environment gotchas
- `EXPORT_DIR` must be the full Confluence export root containing `documents/`, `assets/`, `manifest.jsonl`, and `image_manifest.jsonl`; do not point it at `documents/` alone.
- `processed_image_manifest.jsonl` is generated by `process-images`; image chunks and answer images depend on it.
- Default deployment talks to services on `10.203.97.4` (`QDRANT_URL`, `EMBEDDING_URL`, `RERANK_URL`, `LLM_URL`) while this app publishes the RAG API on local port `8090`.
- If WebUI is accessed from another machine, update `RAG_ASSET_BASE_URL`; the default `127.0.0.1` only works from the VM itself.
- `app-vm-3-17.env.example` contains a real-looking `QDRANT_API_KEY`; avoid copying secrets into new docs or commits.

## Tests and verification
- There is no pytest config, lint, typecheck, CI, Makefile, or pre-commit setup in this repo.
- Most tests are standalone scripts under `pmt_faq_bot/tests/` that add `pmt_faq_bot/` to `sys.path`; run focused tests from the repo root with `python pmt_faq_bot/tests/test_parser.py` or similar.
- Some tests are unittest-style and can run with `python -m unittest discover -s pmt_faq_bot/tests -p 'test_*.py'`, but several files use bare `test_*` functions only, so direct script execution is safer for focused checks.
- `pmt_faq_bot/tests/test_retrieval.py` is an integration/eval harness requiring Qdrant, embedding, rerank, and usually LLM services; set `ENABLE_QUERY_REWRITE=false` if no LLM is available, and run it in the Docker network as documented in that file.
- `test_e2e_real_docs.py` skips when its historical `confluence-dify-clean-export/documents` path is absent; do not treat skipped real-doc output as a full ingestion verification.

## Build/runtime quirks
- Dockerfile supports air-gapped builds: if `pmt_faq_bot/wheels/` exists it installs with `--no-index --find-links`; otherwise it uses PyPI.
- Ingest mode defaults to incremental (`INGEST_MODE=auto`) and hashes raw markdown plus processed image metadata; parser/chunker/filter changes do not make unchanged files re-ingest, so use `--mode full`/`INGEST_MODE=full` when rebuilding derived chunks.
- Retrieval depends on BM25 state stored in Qdrant; changing chunking, parser output, or low-value filters can require re-ingest before retrieval tests are meaningful.
- Changing embedding model or `EMBED_DIM` against an existing Qdrant collection can cause vector-dimension mismatches; recreate/use a new collection before ingesting.
