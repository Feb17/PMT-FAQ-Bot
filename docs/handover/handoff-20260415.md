- 计划首选：**Qwen3.5-122B-A10B**（~250GB BF16，更快，262K 上下文）
- 用户尚未下载完成，**当前用现有模型跑通**：`Qwen3-235B-A22B-Instruct-2507`
- 工作区 `.env` 曾改为 `Qwen3-30B-A3B-Instruct-2507` 做测试；服务器上实际运行的是 235B（以服务器 `docker compose` / 挂载为准）

### 2. 驱动升级

- R575 已 EOL → 升级到 **R580.126.20**
- 安装前需停止：`ollama`、`nvidia-fabricmanager`，并 `rmmod` nvidia 模块
- Fabric Manager 580 包来源（非 cuda repo）：  
  `https://developer.download.nvidia.com/compute/nvidia-driver/redist/fabricmanager/linux-x86_64/fabricmanager-linux-x86_64-580.126.20-archive.tar.xz`

### 3. Docker 网段与 SSH 冲突

- 客户端网段落在 **172.20.x.x**，Docker 自动分配 `172.20.0.0/16` 导致 SSH 断开
- 已在 [`docker-compose.yml`](docker-compose.yml) 增加自定义网络 **`10.88.0.0/24`**
- 建议长期：在 `/etc/docker/daemon.json` 增加 `default-address-pools` 为 `10.89.0.0/16`

### 4. Air-gapped 注意

- 容器内 **不要** 依赖 HuggingFace 联网
- `vllm bench serve` 必须加：`--tokenizer /model`（模型挂载路径）
- Chat API：`--endpoint /v1/chat/completions`
- ShareGPT 数据集需 **JSON 数组**，`.jsonl` 需先转换

## 性能测试（已跑通）

在 `vllm-chat` 容器内执行 `vllm bench serve`（random, 100 prompts, request-rate inf）：

| 指标 | 结果 |
|------|------|
| Output throughput | ~3139 tok/s |
| Total throughput | ~9416 tok/s |
| Mean TTFT | ~359 ms |
| Mean TPOT | ~30 ms |
| 成功率 | 100/100 |

对比：Qwen 官方 H20×8 TP=8 SGLang 单请求约 **74.5 tok/s**（batch=1）；当前为高并发批处理场景，总吞吐高属正常。

**推荐后续 benchmark：**

```bash
docker exec -it vllm-chat bash
vllm bench serve \
  --backend openai-chat \
  --base-url http://localhost:8000 \
  --endpoint /v1/chat/completions \
  --model Qwen3-235B-A22B-Instruct-2507 \
  --tokenizer /model \
  --dataset-name random \
  --random-input-len 512 \
  --random-output-len 256 \
  --num-prompts 100 \
  --request-rate inf
```

可调：`--request-rate 1/5/10`、`--max-concurrency N`、ShareGPT 自定义数据（转 JSON 后 `--dataset-path`）。
